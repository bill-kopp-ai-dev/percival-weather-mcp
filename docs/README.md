# Documentation map — `percival-weather-mcp`

This directory holds everything that is **not** the README, the code or the
CHANGELOG. The README is the entry point for users and operators; this file
explains what each remaining document is for and which one wins when two of
them disagree.

## Precedence

When two documents state different things, resolve in this order:

1. **The code and its tests** — `src/percival_weather_mcp/`, `tests/`.
2. **Generated exports** — `docs/tools.json`,
   `docs/mcp/percival-weather-mcp/oci-label.*` and `tools.json`. They are
   produced by the code and verified by CI, so a mismatch is a build failure,
   not an ambiguity.
3. **`README.md`** — the operational contract: tools, transports, environment,
   wiring and security.
4. **Current guides and decision records** — `percival-integration-guide.md`
   and `decisions/`.
5. **Local working records** — the `internal/` directory at the repository
   root. These are the *history*: campaign plans, issue trackers and their
   evidence. They are never updated to match later code, they must not be
   read as the current contract, and they are not published with the product
   (see "Local-only records" below).

Everything in this directory is published with the product. Nothing here
describes the owner's internal process, and no document in this tree points at
a record that is not published.

## Local-only records

The repository root holds an `internal/` directory that is **gitignored**: it
never reaches the public repository. It carries the Stage-2 remediation plan,
the WX-RF functional plan and implementation report, the native verification
evidence and the functional test campaign records (12 findings, with their
evidence).

Those records document internal process — owners, decisions, local paths and
cross-repository work — and are of no use to a consumer of the server. Where
a public document needs them, it says so in prose instead of linking.

The records are not lost, only unpublished: they remain in the working
checkout and in the repository history. If a future release needs to cite
them, restore the directory from the history rather than reintroducing it
into the published tree.

## Generated artifacts

Two artifact families are generated and must never be hand-edited:

```bash
# tool/prompt/resource snapshot (canonical, referenced by the tests)
uv run python -m percival_weather_mcp.tool_export > docs/tools.json

# registry dump + OCI label artifacts consumed by the Docker MCP gateway
uv run python -m percival_weather_mcp.tool_export --registry \
    > docs/mcp/percival-weather-mcp/tools.json
uv run python scripts/build_oci_label.py          # writes oci-label.{json,yaml,inline}
uv run python scripts/build_oci_label.py --check  # CI gate: exits non-zero on drift
```

`mcp.yaml` (repository root, embedded in the image at `/mcp/mcp.yaml`) is
**hand-maintained**: it mirrors the label's field layout for human inspection.
Its tool and prompt names are pinned by `tests/test_mcp_yaml.py`.
